# Полный сервис: простой запуск

Здесь запускается веб-приложение: загрузка аудио/видео, очередь заданий, история, редактор стенограммы и экспорт TXT / Markdown / Word / PDF. Это не notebook. Python, Git, Jupyter, FFmpeg и pip на компьютере оператора не нужны: зависимости сервиса находятся в подготовленном Docker-образе.

**Перед первым запуском IT должен подготовить среду.** Исходный ZIP не содержит Docker, готовый образ приложения или веса модели. Если корпоративная политика запрещает Docker, PowerShell или локальное выполнение, попросите IT предоставить адрес размещённого сервиса. Не устанавливайте инструменты в обход IT, не меняйте Execution Policy и не запускайте скрипты с повышенными правами ради обхода блокировки.

## Оператор: три шага

1. Получите у IT подготовленную папку проекта и операторский токен. Если папка передана архивом, распакуйте её целиком в разрешённое место. Не запускайте отдельный `.cmd` прямо из ZIP.
2. Дважды нажмите `easy-start/START.cmd`. После успешной проверки launcher откроет `http://127.0.0.1:8000` в браузере; при необходимости откройте адрес вручную. Docker должен быть уже установлен, разрешён и запущен.
3. Для входа откройте `easy-start/LOGIN-TOKEN.cmd`, подтвердите копирование словом `COPY` и вставьте токен в поле входа. Затем очистите буфер обмена. Загрузите запись, которую вам разрешено обрабатывать, подтвердите полномочия и дождитесь завершения. Проверьте текст в редакторе и скачайте нужный формат.

Для размещённого IT сервиса используйте выданный IT адрес и способ входа; локальные `.cmd` не нужны.

Токен оператора — значение `APP_API_TOKEN` из локального `.env`. Launcher не печатает его в консоль; `LOGIN-TOKEN.cmd` копирует его только после вашего подтверждения. При включённых истории или синхронизации буфера обмена возможны дополнительные копии: используйте одобренные IT настройки и удалите сохранённую запись. `ASR_API_TOKEN` предназначен для внутренней интеграции, а не для входа в интерфейс. Не помещайте токены в адрес браузера, скриншоты или обращения в публичную поддержку. Вкладка хранит операторский токен в `sessionStorage`; кнопка выхода удаляет его.

- `easy-start/CHECK.cmd` — проверить Docker, локальный образ, конфигурацию и SHA-256 файлов модели; сообщить о недостающих компонентах.
- `easy-start/STOP.cmd` — после проверки сессий подтвердить остановку словом `STOP`. Данные и модель сохраняются. Сначала остановите Teams-сессии через интерфейс, проверьте фактический выход ботов и разберите `needs_review`; сам launcher этого не подтверждает. Не выключайте приложение во время нужной расшифровки.
- Повторный `START.cmd` использует локальный образ и модель. Обычный запуск не должен скачивать веса или собирать образ.

## Один раз: подготовка для IT

### До запуска подготовки

Проверьте разрешение на Docker и выполнение скриптов, лицензионные условия выбранного Docker-продукта, сетевые источники сборки и обработки данных. Скрипты проекта не устанавливают Docker, не запрашивают администраторское повышение и не меняют корпоративные политики. Нужны работающий Docker с Linux containers и Compose v2, разрешённый PowerShell и браузер. Python и Git на хосте не нужны для easy-start.

Планируйте ресурсы под ограничения CPU Compose: до 4 CPU и 8 GB памяти для приложения, плюс память Docker и ОС. Модель занимает примерно 883 MB; образ, зависимости, временные WAV, загруженные записи и история требуют дополнительного места. Это ориентир для пилота, не обещание скорости реального времени или параллельных встреч.

### Сборка и модель

В папке проекта используйте отдельный вход подготовки `easy-start/IT/PREPARE.cmd`. Прежде чем продолжить, прочитайте запрос и введите `PREPARE`, только если эти действия разрешены: этап создаёт локальные токены при отсутствии `.env`, строит образ и скачивает закреплённую модель. Подтверждение относится к конкретной подготовке; оно не заменяет корпоративное согласование.

Сборка использует Dockerfile проекта. Загрузка модели выполняется внутри подготовленного образа через `scripts/download_models.py`, с закреплёнными revisions и SHA-256; каталог модели размещается в `models/gigaam`. В обычном runtime этот каталог подключается read-only, автоматического скачивания и внешнего STT fallback нет. Подготовка требует интернета к источникам образа, системных/Python-зависимостей, исходников GigaAM и модели; разрешайте их через принятый в организации процесс.

Если `.env` отсутствует, подготовка создаёт его с новыми токенами; существующий файл не перезаписывается. Локальная конфигурация `.env` должна содержать разные сильные `APP_API_TOKEN` и `ASR_API_TOKEN`; оператору нужен только первый. Храните файл в доступном только уполномоченным пользователям месте. Не включайте подготовленный `.env` в общий исходный ZIP. Оставьте `TEAMS_ENABLED=false` для локальной загрузки файлов.

После подготовки запустите `easy-start/CHECK.cmd`, затем `easy-start/START.cmd` и обработайте короткую разрешённую тестовую запись. Проверка файлов и ответ `/healthz` не доказывают загрузку нейросети: критерий приёмки — успешно завершённое задание и проверенная стенограмма. До корпоративных данных настройте защиту диска, backup и retention по [OPERATIONS.md](OPERATIONS.md) и [SECURITY.md](../SECURITY.md).

### Отдельная офлайн-передача

На разрешённом подключённом компьютере IT сначала подготавливает и проверяет образ и модель. Затем из папки проекта можно сохранить образ отдельно от архива исходников:

```bat
docker image save --output teams-asr-platform-image.tar teams-asr-platform:local
```

Передайте через согласованный канал исходники, `teams-asr-platform-image.tar` и весь проверенный каталог `models/gigaam` вместе с его `provenance.json` и лицензией. Зафиксируйте контрольные суммы передаваемых файлов и проверьте их на получателе; передача checksum тем же недоверенным каналом не подтверждает подлинность. Docker и Compose на целевом компьютере также должны быть заранее одобрены и подготовлены IT.

На целевом компьютере после проверки происхождения архива:

```bat
docker image load --input teams-asr-platform-image.tar
```

Разместите `models/gigaam` в папке проекта и подготовьте отдельные локальные токены для этой установки. Затем выполните обычные проверки и тестовую расшифровку. Не запускайте онлайн-подготовку ради офлайн-старта: отсутствие образа/модели — повод вернуть комплект на доработку IT. Тег образа удобен для запуска, но сам по себе не доказывает его происхождение; IT должен сохранить digest/идентичность проверенной сборки.

## Если не запускается

- Docker отсутствует, не работает или запрещён: передайте результат проверки IT. Запросите разрешённый сервис URL, если локальная среда недоступна.
- PowerShell заблокировал скрипт или просит доверия/подписи: остановитесь. IT должен проверить источник и предоставить разрешённый способ запуска; не используйте `ExecutionPolicy Bypass`, отключение защиты или обход политики.
- Нет локального образа или весов: нужен завершённый этап подготовки IT либо полный офлайн-комплект. Исходный ZIP этого не заменяет.
- Порт 8000 занят: не завершайте неизвестный процесс. Попросите IT проверить, не запущена ли уже другая копия приложения.
- Страница отвечает, но задача не завершилась: сохраните ID задания и безопасный текст ошибки. Не прикладывайте токены, запись или стенограмму к общедоступному отчёту.
- Расшифровка медленная или нет места: не добавляйте новые задания; попросите IT проверить очередь, CPU/RAM и диск. Не запускайте второй экземпляр против той же базы.

## Teams и границы проверки

Teams — отдельный необязательный экспериментальный коннектор. Установка сервиса и наличие поля Teams не означают настроенный tenant, доступ к встречам или право записывать участников. Нужны отдельное согласование, Vexa на выделенной среде, настройки токенов/сети, allowlist встреч и авторизованный пилот по [TEAMS_CONNECTOR.md](TEAMS_CONNECTOR.md). Реальное подключение к Teams в корпоративном tenant не проверено. Если IT уже настроил `TEAMS_ENABLED=true`, launcher подключает `deploy/compose.teams.yaml`, проверяет наличие обязательных параметров и сети `teams-asr-vexa`; он не создаёт Vexa и не проверяет реальный join. Остановка локального приложения не гарантирует выход отдельно работающего Vexa-бота.

Локальный inference/API и тесты описаны в [TEST_REPORT.md](TEST_REPORT.md). Не переносите их результат на Windows launcher, Docker deployment, реальные встречи, нагрузку или качество трёх языков без проверки целевой среды. Windows PowerShell/Docker runtime этой версии launcher не запускались в среде разработки. Это одноузловой пилот с общим операторским доступом, без встроенных SSO/RBAC, tenant isolation и HA.

## Что входит в полный исходный архив

Код приложения, Docker/Compose и скрипты, тесты, документация, лицензии и все notebook в `notebooks/`. Для обычного сервиса notebook запускать не нужно. Python 3.13 notebook остаётся отдельным вариантом «микрофон → текст»: [его инструкция](PYTHON313_VSCODE.md).

Архив не содержит веса модели, готовый Docker-образ, `.env`/секреты, пользовательские данные, записи, стенограммы, скачанный `vendor`, виртуальные окружения, caches или сгенерированные outputs. Полные исходники и готовая офлайн-среда — разные комплекты; IT подготавливает второй отдельно.

### Изоляция Teams-бота

Vexa запускается только на выделенной одноразовой VM: управление Docker socket даёт фактически привилегированный доступ к хосту, а браузерный бот работает с `--no-sandbox`. Не запускайте этот стек на личном ноутбуке или общем корпоративном Docker-хосте. После пилота VM утилизируется по согласованной политике хранения данных.
